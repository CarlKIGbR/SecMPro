### 4.12 `store` — local-store constructions (ADR-053 items 1–6, Amendment 1; spec rev 2.7)

*Source: ADR-053 (`docs/08`), items 1–8, its Appendix and Amendment 1, with spec rev 2.7 App. A (the four store
labels) and §3.4 (CAEAD). Generated by `ref/tools/render_schema_4_12.py` from `ref/secmp_ref/store_cases.py`, the
table that generates `store.json`. Weisung REF-M7-store.*

Suite `store`, tag `store` (SCHEMA §3), header `"schema": 8` and `"spec": "SecMP/1 rev 2.7"`. 19 cases, ids
`store-0001` … `store-0019`: 8 positive, 11 `"expect": "reject"`. Every random-looking input comes
from the case's stream (SCHEMA §2, suite name `store`, the case index), in the order listed per op; a reject case
draws nothing and restates the inputs of the case it manipulates (`from`). Passphrases are UTF-8, written as hex.
Column names are case inputs, not schema claims. Argon2id is checked against RFC 9106 §5.3
(`tests/test_kat_argon2.py`, p = 4).

**Field shapes (schema 8).** Byte strings are lowercase hex. `label`, `column` and `manipulation` are ASCII
strings. `row_key_parts` is a list, in primary-key order, of `{"int": n}` (a JSON integer, encoded as u64
big-endian; a negative integer is not encodable, Am. 1) or `{"bytes": hex}` (encoded `len u8 ‖ bytes`). A positive
`seal` case carries `from` (the `keys` case its `k_t` is derived from). A reject case carries `from`,
`manipulation` and `"expect": "reject"`, and no `outputs`; every reject is the one uniform error.

**Constants.** `PROFILE` = (m, t, p) = (262144, 3, 4), written `m u32 ‖ t u32 ‖ p u32` big-endian (12 B); `ver` = 0x01;
`salt` 16 B, `n` 24 B, `MK` 32 B; HKDF salt 0^32; wrap 133 B; bwrap 104 B; backup header 154 B;
backup magic `"SecMProbackup"` (13 B).

**Obligations per op.**
- `keys`: `k_<table>` = HKDF-SHA-256(salt 0^32, IKM `mk`, info `"SecMP-STORE/1 <table>"`, L 32) for the nine tables;
  `k_db` with info `"SecMP-STORE/1 db"` (items 3–4).
- `wrap`: `kek` = Argon2id(passphrase, salt, PROFILE, T 32); `wrap` = `01 ‖ salt ‖ params ‖ n ‖ CAEAD.Seal(kek, n,
  "SecMP-STORE/1 wrap" ‖ ver ‖ salt ‖ params, mk)` (items 1–2).
- `wrap-reject`: unlocking `wrap` with `passphrase` fails. The `ver` and `params` rows are honestly sealed under their
  own header (and KEK), so that only the acceptance rule rejects them; the rule is decided before the KDF (item 2).
- `seal`: `row_key` per item 5 / Am. 1; `ad` = `label ‖ col_len u8 ‖ column ‖ row_key`; `rec` = `n ‖ CAEAD.Seal(k_t, n,
  ad, record)`; `k_t` is `k_<table>` of the `keys` case named by `from`.
- `seal-reject`: opening `rec` under the stated key, label, column and row key fails; the `-1` row has no `rec`: the
  row key is not encodable.
- `backup`: `kek_bk` = Argon2id(passphrase, salt, PROFILE); `bwrap` = `n_prime ‖ CAEAD.Seal(kek_bk, n_prime,
  "SecMP-STORE/1 bwrap" ‖ ver ‖ salt ‖ params, mk_bk)`; `k_bk` = HKDF(0^32, `mk_bk`, `"SecMP-STORE/1 backup"`, 32);
  `header` = `01 ‖ salt ‖ params ‖ bwrap ‖ 04 ‖ {tag ‖ len u32} × 4` (tags 1–4, lengths 97, 4, 2, 4); `body` = the four
  sections (identity = `01 ‖` the 96 stream bytes of `identity`'s tail, contacts `00000000`, settings `0000`,
  messages `00000000`); `file` = magic ‖ header ‖ `n` ‖ CAEAD.Seal(`k_bk`, `n`, `"SecMP-STORE/1 backup"` ‖ header, body).
- `backup-reject`: opening `file` with `passphrase` fails. The `params` row and the `bwrap-label=wrap` row are
  honestly built (the latter seals `bwrap` under `"SecMP-STORE/1 wrap"`), so that only the named defect rejects them.

**Stream layouts** (name, bytes), in order: `keys`: `mk` 32; `wrap`: `salt` 16, `n` 24, `mk` 32; `seal`: `n` 24, the 16-B
byte-string key part where the row has one, `record`; `backup`: `salt` 16, `n_prime` 24, `mk_bk` 32, `n` 24, `identity_secrets` 96, where `identity` is `01` ‖
`identity_secrets`.
