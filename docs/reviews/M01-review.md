## B. Spec conformance — verified by reading the code

- **Labels (`label.rs`):** 49 labels in Appendix A order; `enum_equals_appendix_a_of_the_spec` and `label_set_is_prefix_free` re-read `docs/03-protocol-spec.md` via `include_str!` (ADR-035); the three rev 2.2 renames present, old names rejected; `HybridSign` accepts exactly `HxBundle`/`TrKeychange`.
- **HKDF (`kdf.rs`):** `info = label ‖ context` unframed; empty salt ≡ `0^32`; expand-only from `PRK ≥ 32`; `L ≤ 8160`; composition verified against a manual HMAC construction.
- **X25519 (`x25519.rs`):** RFC 7748 input handling inside `x25519-dalek`; all-zero output rejected in constant time (covers every low-order input; tested with u = 0, 1, order-8 point, p−1, p, p+1); RFC 7748 §5.2 vector 2 (top bit set) passes.
- **ML-KEM (`mlkem.rs`):** decapsulation keys held as the 64-byte seed `d ‖ z` in `LockedSecret`, expanded per use and zeroised; encapsulation keys validated on import (`validate_public_key`, FIPS 203 §7.2); ciphertexts length-typed; implicit rejection is not an error and is deterministic (tested).
- **HybridKEM (`hybrid_kem.rs`):** combiner `SHA3-256(ss_kem ‖ ss_dh ‖ SHA3-256(ct_kem) ‖ SHA3-256(ek_kem) ‖ pk_dh ‖ pk_e ‖ V)` in exactly this order with the raw ASCII label; decapsulation recomputes its own `ek_kem`/`pk_dh` and hashes the received `pk_e`/`ct_kem` bytes (ref reading 3); low-order `pk_dh`/`pk_e` rejected on both sides; tampering changes the secret without an error (Appendix C).
- **MsgEncrypt (`msg.rs`):** `HKDF(0^32, MK, "SecMP-TR/1 msgkeys", 76)` split 32/32/12; ChaCha20 from block counter 0; `TAG = HMAC(K_mac, AD ‖ C)`; `|P| = 1710` and `|C ‖ TAG| = 1742` enforced with the uniform error; tag compared in constant time before any decryption; `MK` consumed by value on sealing.
- **CAEAD (`caead.rs`):** `HKDF-Expand(PRK = K, "SecMP-commit/1" ‖ N, 64) → K_enc ‖ COM`; output `COM ‖ C` without `N`; open evaluates the commitment comparison (`ct_eq`) and the AEAD in every case and returns one `Rejected`.
- **Ed25519 (`ed25519.rs`):** the four byte-level rules of §3.5 are checked by first-party code before the library runs — `S < L`, canonical `A`/`R` (y < p), no small-order `A`/`R` (the five torsion y-values, both signs; the table was checked by the reviewer against the known encodings); `A` on import, `R`/`S` before `verify_strict`. The report's finding that `ed25519-dalek 3.0.0` accepts a non-canonical `A` is demonstrated by a test, which is exactly why the spec demands first-party checks.
- **ML-DSA-65 (`mldsa.rs`):** pure (`M' = 0x00 ‖ len(ctx) ‖ ctx ‖ m` via `sign_internal`), hedged with 32 bytes of OS randomness, keys from the 32-byte seed in locked memory, `ctx ≤ 255`.
- **HybridSign (`hybrid_sign.rs`):** `m = SHA-256("SecMP-HybridSign/1" ‖ label ‖ M)`; `sig = sig_ed (64) ‖ sig_mldsa (3309)` = 3373 (const-asserted); ML-DSA `ctx = label`; verification evaluates both components (non-short-circuit) and refuses foreign labels with the same `Rejected`.
- **Fingerprint / SAS (`fingerprint.rs`, `sas.rs`):** `SHA-256("SecMP-FP/1" ‖ iks)` with `|iks| = 2017` enforced; 5 200 iterations of `SHA-256("SecMP-SAS/1" ‖ h ‖ fp)`, six 5-byte groups from bytes 0–29, zero-padded decimal, ascending constant-time sort and swap.
- **Secrets (`secret.rs`, `nonce.rs`, `rng.rs`):** `SecretBytes` (boxed, zeroised on drop, no `Clone`/`Debug`/`PartialEq`, `ct_eq`), `LockedSecret` over `SecretPage`; every key, ciphertext and fingerprint type has a redacted `Debug`; `Nonce24`/`Counter64` consumed by value, strict `+1` on receive, overflow is an error; `getrandom` is the only randomness source.
- **`SecretPage` (`secmp-sys-mem`):** `[guard | data | guard]`; Linux `memfd_secret` (`MAP_FIXED` over the data page, `MADV_DONTFORK`) with the `mlock` + `MADV_DONTDUMP` + `MADV_WIPEONFORK` fallback; Windows `VirtualLock` with one working-set enlargement; Miri heap backend; fail closed; every `unsafe` block carries a `SAFETY:` comment and does one thing; the OS view is tested (pipe-`write(2)` EFAULT probe of the guard pages, `VmFlags` `lo`/`dd`/`wf`|`dc` in `/proc/self/smaps`, `VirtualQuery`).

Invariants (CLAUDE.md §1): no primitive implemented locally (the only byte arithmetic is the §3.5 encoding checks and the §6.7 digit conversion, both required by the spec); one uniform `Error::Rejected` for every input-dependent failure; no `unsafe` outside the two sys crates (policy-checked); no `#[allow]` beyond the sanctioned test allowance (`expect::TEST_FILE_ALLOWANCE`) and the two sys-crate roots; no build scripts in first-party crates; every dependency `=`-pinned with an ADR line and a vet record; normal closure of `secmp-crypto`/`secmp-proto` = 52 crates, 0 exemptions (computed per target over normal edges only, `xtask/src/meta.rs`, unit-tested); 25 tracked exemptions all outside it (build-only, dev-only, wasm32/UEFI-only, `cfg(hax)`/`cfg(valgrind_ct_test)`-only).
