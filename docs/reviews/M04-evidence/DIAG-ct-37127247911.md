## Q1 — criterion

**Control.** `Sensitivity::raw_delta` (`ct.rs:3338-3340`) = `measurement.raw().delta()` = mean(class 0) − mean(class 1) over all 1 000 000 uncropped samples. `reached` (`ct.rs:3343-3345`) = `matches!((raw_delta, floor_ticks), (Some(d), Some(f)) if d >= f)`. The floor is that measurement's floor (`ct.rs:3408`). `sensitivity_control` (`ct.rs:3385-3412`) measures `min_leak` **once**, with `tag_compare`'s k (here 1) and sample count, after the full A/A pass (`ct.rs:3297-3298`). It has no t threshold, no crop, no second measurement, and the sign is fixed (class 0 slower). The failure text is at `ct.rs:3347-3359`; module doc `ct.rs:136-138`.
ADR wording: ADR-041 Am. 1 (2) (`adr:15`): "its raw Δ must reach the floor in every run, otherwise the run's verdict is `CONTROL_FAIL`; it records the gate's sensitivity per run". ADR-042 Am. 1 (`adr:30`): "fix the control, not the rule — ADR-041's criterion, including its sign (class 0 slower), stays". Consequences of ADR-041 Am. 1 (`adr:16`): "every run proves that sensitivity through `min_leak_control`".

**Targets.** `evaluate` (`ct.rs:1198-1306`) takes two measurements (`measure_pair` `ct.rs:1230-1246`). `decide` (`ct.rs:1147-1179`) works per crop over raw, p50, p75, p90, p95 and p99 (`CROPS_PERMILLE` `ct.rs:204`; `analyse` `ct.rs:771-791` keeps the samples below the pooled percentile):
- *reproduced* ⇔ \|t1\| > 4.5 ∧ \|t2\| > 4.5 ∧ same sign;
- *relevant* ⇔ \|Δ1\| ≥ floor(m1) ∧ \|Δ2\| ≥ floor(m2);
- FAIL if any crop is reproduced and relevant (the crop with the strongest min(\|t1\|,\|t2\|) decides); SUB_FLOOR_SHIFT if reproduced but none relevant; PASS otherwise. Either sign counts.

The positive control is measured once and passes if max \|t\| > 4.5 (`ct.rs:1289-1297`). The A/A control passes if max \|t\| ≤ 4.5 over all crops (`ct.rs:3483-3513`).

**Comparison.** The statistics differ. The control uses one statistic, the raw mean, which is the one most exposed to differences in class shape and to tails; it fixes the sign and has no significance or reproduction requirement. Targets take the most sensitive of six crops. For this failure mode the control is therefore stricter. In significance it is laxer: no t, no second measurement.
Consequence in this run: applied to the control's own data, the target rule finds the leak at p50, p75 and p90 (Δ 6.22, 6.27 and 3.08 floors; t 204, 260 and 140). With one recorded measurement, reproduction cannot be checked. The verdict rule was sensitive to the minimal leak in this run. The raw-mean criterion tested a statistic that the verdict rule never uses on its own.

## Q5 — `ct-bench.log` is 0 bytes

- The gate builds the bench with `cargo bench --locked -p secmp-testkit --features kat --bench ct --no-run --message-format=json-render-diagnostics` through `Cmd::read()` (`xtask-diff:600-614`). That output is consumed by xtask to find the executable and is never written to the log.
- The gate then runs `<exe> --bench` with stdout and stderr in `target/ct-bench.log` (`run_ct_bench` → `run_budgeted` → `cmd.spawn_logged(log)`, `xtask-diff:649-676, 733-753`, `743`). `spawn_logged` lives in a file that is not among the inputs. The unit test `ct_gate_timeout_is_a_fail_naming_the_target` asserts that `"bench output"` reaches the log (`xtask-diff:2412-2473`), so the capture works.
- The bench writes nothing to stdout or stderr by design. There is no `println`/`eprintln` anywhere in `ct.rs`; the progress function is "a file, never stdout (docs/06 §2)" (`ct.rs:3524`); the report and progress are files (`ct.rs:3519-3550`).
- So a 0-byte log is the expected result of a normal exit. It positively shows that there was no panic or abort message.
- Defect of the evidence design rather than of the code: ADR-045 Am. 1 (`adr:39`) asks for stdout+stderr in the log so that a failed run "leaves a trace", but the log can only ever hold a panic message. It carries no build line, no `rustc -vV`, no executable path or sha256, and no CPU model or microcode. That identity is exactly what this diagnosis lacks to separate "layout" from "host".
- Cheap remedy (gate-side, no criterion change): write those identity lines into the log header, or into the report's `clock`.
