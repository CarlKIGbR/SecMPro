== root cause (M3 review C1) ==
xtask/src/gates.rs (test `gates::tests::the_nightly_workflow`, the assertion at :2174 at 665e84e): the test searches
include_str!(".github/workflows/fuzz-nightly.yml") for multi-line needles written with \n ("on:\n  schedule:\n").
GitHub's Windows images check the repository out with core.autocrlf=true, so the compiled-in file holds \r\n and
the needle cannot match; the panic message prints that needle ("on:" / "  schedule:"). Linux and macOS check out
LF, so the test passed there (linux-fast success). A harness defect in an xtask unit test: no product code and no
gate behaviour is involved (the workflow parsers of the policy step read line by line and are CRLF-safe).
Fix: the test normalises CRLF to LF before matching and also runs every check on a CRLF copy of the file, so the
Windows condition is exercised on every host; with the normalisation removed, the CRLF arm fails exactly as
windows-native did (verified locally on macOS).
